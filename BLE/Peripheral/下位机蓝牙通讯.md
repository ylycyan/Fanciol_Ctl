# 蓝牙通讯协议文档

本文档描述了基于沁恒CH583的红外分体空调控制器与上位机之间的蓝牙通讯协议。

## 1. 协议概述

- **服务 UUID**: `0xFFE0` (SimpleProfile)
- **指令通道**: `0xFFE1` (Characteristic 1) - 支持 Read / Write / Notify
- **透传通道**: `0xFFE2` (Characteristic 2) - 支持 Write / Notify (用于红外数据透传)
- **状态通道**: `0xFFE3` (Characteristic 3) - 仅 Notify (用于周期性状态推送)
- **数据大小端**: 小端模式 (Little Endian)，低字节在前

## 2. 帧结构

所有指令和响应均遵循以下帧结构：

| 字节偏移 | 长度 (Byte) | 字段 | 说明 |
| :--- | :--- | :--- | :--- |
| 0 | 1 | **LEN** | 总长度 (包含 LEN 本身, CMD, Payload, CRC) |
| 1 | 1 | **CMD** | 指令类型 |
| 2 ~ N | N-3 | **Payload** | 数据负载 (可选) |
| N-1 | 1 | **CRC** | 校验和 |

**CRC 算法**:
```c
uint8_t CalcCrc(uint8_t *buf, uint16_t len_without_crc) {
    uint8_t crc = 0;
    for (int i = 0; i < len_without_crc; i++) {
        crc += buf[i];
    }
    return crc + 0xEC;
}
```

## 3. 指令定义 (CMD)

| CMD | 值 | 方向 | 说明 | Payload 格式 |
| :--- | :--- | :--- | :--- | :--- |
| **WRITE** | 0x01 | 上位机->设备 | 写属性 | `[PID][Value] [PID][Value]...` |
| **READ** | 0x02 | 上位机->设备 | 读属性 | `[PID] [PID]...` |
| **NOTIFY** | 0x03 | 设备->上位机 | 属性通知/应答 | `[PID][Value] [PID][Value]...` |
| **ACK** | 0x04 | 设备->上位机 | 操作成功应答 | 无 (或包含补充信息) |
| **ERROR** | 0x05 | 设备->上位机 | 错误应答 | `[Error String]` |
| **ACTION** | 0x06 | 上位机->设备 | 执行动作 | `[ActionID] [Params...]` |

**写入说明**:
- WRITE 即时控制类属性: SWITCH / MODE / TEMP_SET / FAN_SPEED / LOCK
- WRITE 设备参数配置类属性: LORA_CFG / IR_CFG / SYS_CTRL，设备侧会延时保存参数到 Flash

## 4. 属性定义 (PID)

用于 `WRITE` / `READ` / `NOTIFY` 指令中标识数据类型。

| PID | 值 | 数据类型 | 说明 |
| :--- | :--- | :--- | :--- |
| **SWITCH** | 0x01 | uint8 | 开关状态 (0:关, 1:开) |
| **MODE** | 0x02 | uint8 | 运行模式 (0:自动, 1:制冷, 2:除湿, 3:送风, 4:制热) |
| **TEMP_SET** | 0x03 | uint16 | 设定温度 (放大10倍传输, 如 26.5℃ 传 265) |
| **TEMP_ROOM** | 0x04 | int16 | 环境温度 (放大10倍传输) |
| **FAN_SPEED** | 0x05 | uint8 | 风速 (0:自动, 1:低, 2:中, 3:高) |
| **LOCK** | 0x06 | uint8 | 锁定状态 |
| **ERROR** | 0x07 | uint16 | 故障码 (按位定义) |
| **LORA_CFG** | 0x10 | Struct | Lora配置: `NodeID(2) + Channel(1)` |
| **IR_CFG** | 0x11 | Struct | 红外配置 (见 4.4) |
| **DEV_INFO** | 0x12 | Struct | 设备信息: `RunTime(2) + Power(2)` |
| **SYS_PARAMS** | 0x13 | Struct | 系统运行参数查询 (见 4.2, 18 Bytes) |
| **SYS_CTRL** | 0x14 | Struct | 系统参数控制 (见 4.3, 4 Bytes) |
| **IR_MATCH** | 0x15 | Struct | 红外匹配结果 (见 4.5) |
| **IR_LEARN** | 0x16 | Struct | 红外学习控制 |
| **IR_LEARN_LIST** | 0x17 | Struct | 学习通道列表 (READ → 返回10字节 enable 状态) |
| **ALL_STATE** | 0xF0 | Struct | **全状态查询** (聚合核心状态，仅用于 READ/NOTIFY, 见 4.1) |

### 4.1 ALL_STATE 返回数据结构 (9 Bytes)
当读取 `PID_ALL_STATE` 时，返回的数据顺序如下：
1. `SWITCH` (1 Byte)
2. `MODE` (1 Byte)
3. `TEMP_SET` (2 Bytes)
4. `TEMP_ROOM` (2 Bytes)
5. `FAN_SPEED` (1 Byte)
6. `ERROR` (2 Bytes)

### 4.2 SYS_PARAMS 返回数据结构 (18 Bytes)
当读取 `PID_SYS_PARAMS` 时，返回的数据顺序如下：
1. `nodeId` (2 Bytes)
2. `channel` (1 Byte)
3. `loraStatus` (1 Byte)
4. `scanCycle` (1 Byte)
5. `irType` (2 Bytes)
6. `irIdx` (1 Byte): 空调品牌索引
7. `irActType` (1 Byte): 动作类型 (0:红外控制, 1:红外学习)
8. `mode` (1 Byte, 0:本地 1:远程)
9. `errorCode` (2 Bytes)
10. `tempRoom` (2 Bytes, 放大10倍)
11. `runTime` (2 Bytes, 分钟)
12. `loadPower` (2 Bytes, W*10)

### 4.3 SYS_CTRL 写入数据结构 (4 Bytes)
当使用 `WRITE` 写入 `PID_SYS_CTRL` 时，数据顺序如下：
1. `nodeId` (2 Bytes)
2. `channel` (1 Byte)
3. `mode` (1 Byte, 0:本地 1:远程)

### 4.4 IR_CFG 写入数据结构
当使用 `WRITE` 写入 `PID_IR_CFG` 时：
- **红外控制模式** (irActType=0): `irActType(1) + irType(2, 小端) + irIdx(1)` = 4 Bytes
- **红外学习模式** (irActType=1): `irActType(1)` = 1 Byte (通道由 PID_IR_LEARN 控制)

**说明**:
- irType: 红外控制码（控制参数），2字节小端
- irIdx: 型号索引，在同一irType下区分不同品牌型号
- 组合空间: 2字节irType × 1字节irIdx = 65535 × 256 = 16,777,216 种组合

### 4.5 IR_MATCH 通知数据结构 (4 Bytes)
当设备完成红外匹配时，通过 `NOTIFY` 返回：
1. `status` (1 Byte)
2. `irType` (2 Bytes, 小端)
3. `modelIndex` (1 Byte)

status 说明:
- 0x00: 匹配成功
- 0x01: 匹配失败
- 0x02: 匹配超时(20s)
- 0x03: 匹配异常

### 4.6 故障码位定义 (ERROR PID, uint16)

| 位 | 说明 |
| :--- | :--- |
| bit 0 | Lora离线 |
| bit 1 | 红外学习异常 |
| bit 2 | 红外匹配异常 |
| bit 3 | AD转换异常 |
| bit 4 | 功率转换异常 |
| bit 5 | Flash(EEPROM)操作异常 |

## 5. 动作定义 (ActionID)

用于 `ACTION` 指令 (CMD=0x06)。

| ActionID | 值 | 参数 | 说明 |
| :--- | :--- | :--- | :--- |
| **RESET** | 0x01 | 无 | 设备复位 |
| **IR_MATCH** | 0x02 | 无 | 触发红外匹配 |
| **IR_LEARN** | 0x03 | `[channel_idx(1)]` | 启动红外学习 (指定学习通道 0~9) |
| **IR_CMD** | 0x04 | `[IR inner code(1)]` | 红外内码指令发送 |
| **SAVE_PARAMS** | 0x05 | 无 | 保存参数到Flash (ACK预留) |
| **IR_LEARN_SEND** | 0x06 | `[channel_idx(1)]` | 发送已学习的红外码 (指定通道 0~9) |

**红外学习通道固定含义**:
| 通道 | 含义 |
| :--- | :--- |
| 0 | 开机 |
| 1 | 关机 |
| 2 | 制冷 |
| 3 | 制热 |
| 4 | 除湿 |
| 5 | 送风 |
| 6 | 温度+ |
| 7 | 温度- |
| 8 | 风速 |
| 9 | 自定义 |

## 6. 通讯示例

### 6.1 查询设备所有状态
**发送 (Read All)**:
- Hex: `04 02 F0 E2`
- 解析: Len=4, Cmd=READ(0x02), PID=ALL_STATE(0xF0), CRC=0xE2

**接收 (Notify All)**:
- Hex: `0D 03 F0 01 01 09 01 14 01 02 00 00 0F`
- 解析:
    - Len: 13 (0x0D)
    - Cmd: NOTIFY (0x03)
    - PID: ALL_STATE (0xF0)
    - Data:
        - Switch: 01 (开)
        - Mode: 01 (制冷)
        - TempSet: 09 01 -> 0x0109 = 265 (26.5℃)
        - TempRoom: 14 01 -> 0x0114 = 276 (27.6℃)
        - Fan: 02 (中速)
        - Error: 00 00 (无故障)
    - CRC: 0x0F

### 6.2 设置温度为 26.0℃ 并 开启设备
**发送 (Write Multi)**:
- Hex: `08 01 01 01 03 04 01 FF`
- 解析:
    - Cmd: WRITE (0x01)
    - PID1: SWITCH (0x01), Val: 01 (On)
    - PID2: TEMP_SET (0x03), Val: 04 01 (260 = 26.0℃)
    - CRC: 0xFF

**接收 (Ack)**:
- Hex: `03 04 F3`
- 解析: ACK (0x04), CRC

### 6.3 发送红外控制内码
**发送 (Action IR_CMD)**:
- Hex: `05 06 04 XX YY`
- 解析:
    - Cmd: ACTION (0x06)
    - ActID: IR_CMD (0x04)
    - IR inner code: XX
    - CRC: YY

**接收 (Ack)**:
- Hex: `03 04 F3`

### 6.4 触发红外匹配
**发送 (Action IR_MATCH)**:
- Hex: `04 06 02 F8`
- 解析:
    - Cmd: ACTION (0x06)
    - ActID: IR_MATCH (0x02)
    - CRC: 0xF8

**接收 (Ack)**:
- Hex: `03 04 F3`

**接收 (Notify IR_MATCH)**:
- Hex: `07 03 15 00 3E 03 4C`
- 解析:
    - Cmd: NOTIFY (0x03)
    - PID: IR_MATCH (0x15)
    - status: 0x00
    - irType: 0x033E
    - CRC: 0x4C

### 6.5 查询系统运行参数
**发送 (Read SYS_PARAMS)**:
- Hex: `04 02 13 05`
- 解析: Len=4, Cmd=READ(0x02), PID=SYS_PARAMS(0x13), CRC=0x05

**接收 (Notify SYS_PARAMS)**:
- Hex: `15 03 13 01 00 05 04 3C 00 01 00 00 10 00 2C 01 2C 01 2C 01 XX`
- 解析:
    - nodeId: 0x0001
    - channel: 0x05
    - loraStatus: 0x04
    - scanCycle: 0x3C
    - irType: 0x0001
    - irIdx: 0x00
    - irActType: 0x00
    - mode: 0x00
    - errorCode: 0x0010
    - tempRoom: 0x012C (30.0℃)
    - runTime: 0x012C (300min)
    - loadPower: 0x012C

### 6.6 设置系统运行参数
**发送 (Write SYS_CTRL)**:
- Hex: `08 01 14 01 00 05 01 10`
- 解析:
    - Cmd: WRITE (0x01)
    - PID: SYS_CTRL (0x14)
    - nodeId: 0x0001
    - channel: 0x05
    - mode: 0x01
    - CRC: 0x10

**接收 (Ack)**:
- Hex: `03 04 F3`

### 6.7 设备重启
**发送 (Action Reset)**:
- Hex: `04 06 01 F7`
- 解析:
    - Cmd: ACTION (0x06)
    - ActID: RESET (0x01)
    - CRC: 0xF7

**接收 (Ack)**:
- Hex: `03 04 F3`

### 6.8 启动红外学习 (通道2-制冷)
**发送 (Action IR_LEARN)**:
- Hex: `05 06 03 02 XX`
- 解析:
    - Cmd: ACTION (0x06)
    - ActID: IR_LEARN (0x03)
    - channel: 0x02
    - CRC: XX

**接收 (Ack)**:
- Hex: `03 04 F3`

### 6.9 发送已学习的红外码 (通道0-开机)
**发送 (Action IR_LEARN_SEND)**:
- Hex: `05 06 06 00 XX`
- 解析:
    - Cmd: ACTION (0x06)
    - ActID: IR_LEARN_SEND (0x06)
    - channel: 0x00
    - CRC: XX

**接收 (Ack)**:
- Hex: `03 04 F3`

### 6.10 查询学习通道列表
**发送 (Read IR_LEARN_LIST)**:
- Hex: `04 02 17 XX`
- 解析: Len=4, Cmd=READ(0x02), PID=IR_LEARN_LIST(0x17), CRC=XX

**接收 (Notify IR_LEARN_LIST)**:
- Hex: `0D 03 17 01 01 01 00 00 00 00 00 00 00 XX`
- 解析: 返回10个学习通道的 enable 状态 (0=空, 1=已学习)

## 7. 本地规则引擎

设备支持本地规则引擎，最多10条规则，每条规则16字节紧凑结构：

| 字节 | 字段 | 说明 |
| :--- | :--- | :--- |
| 0 | ctrl (位域) | enable(1bit) + trig_type(3bit) + executed(1bit) + reserved(3bit) |
| 1 | flags | 时间触发: bit[0~6]=周日~周六, bit7=忽略月份; 条件触发: bit0=锁存, bit1=反向动作 |
| 2~3 | trig_val | 触发主值 (按trig_type复用) |
| 4~5 | trig_val2 | 触发副值 |
| 6~7 | sched | 调度扩展/阈值上限 |
| 8~15 | act | 动作载荷 (IR控制或Learn码索引) |

**触发类型 (trig_type)**:
| 值 | 类型 | 说明 |
| :--- | :--- | :--- |
| 0 | 无触发 | 禁用 |
| 1 | 按时间 | 每日定时 (时:分) |
| 2 | 温度高于 | 环境温度 > 阈值 |
| 3 | 温度低于 | 环境温度 < 阈值 |
| 4 | 功率高于 | 实时功率 > 阈值 |
| 5 | 运行时间 | 累计运行时间 > 阈值 |
| 6 | 累计电量 | 累计电量 > 阈值 |
| 7 | 组合触发 | 时间窗口 + 条件同时满足 |

**动作类型**:
| 值 | 类型 | 说明 |
| :--- | :--- | :--- |
| 0 | ACT_TYPE_IR | 发送红外指令 (空调控制) |
| 1 | ACT_TYPE_LEARN | 发送学习的红外码 |

## 8. OTA固件升级

设备支持通过 BLE 进行 OTA 固件升级，使用专用的 OTA Profile 服务。
