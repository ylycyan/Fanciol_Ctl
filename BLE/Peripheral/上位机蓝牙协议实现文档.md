# 蓝牙通讯协议实现文档

> 本文档整理了上位机小程序实现的蓝牙通讯协议及预期报文格式，用于与下位机代码核对。

---

## 1. 协议基础信息

| 项目 | 值 |
| :--- | :--- |
| **服务UUID** | `0000FFE0-0000-1000-8000-00805F9B34FB` |
| **指令特征UUID** | `0000FFE1-0000-1000-8000-00805F9B34FB` (支持 Notify/Write) |
| **透传特征UUID** | `0000FFE2-0000-1000-8000-00805F9B34FB` (支持 Notify/Write) |
| **数据大小端** | 小端模式 (Little Endian)，低字节在前 |

---

## 2. 帧结构

所有指令和响应均遵循以下帧结构：

| 字节偏移 | 长度(Byte) | 字段 | 说明 |
| :--- | :--- | :--- | :--- |
| 0 | 1 | **LEN** | 总长度(包含LEN自身、CMD、Payload、CRC) |
| 1 | 1 | **CMD** | 指令类型 |
| 2 ~ N | N-3 | **Payload** | 数据负载(可选) |
| N-1 | 1 | **CRC** | 校验和 |

### CRC计算算法

```c
uint8_t CalcCrc(uint8_t *buf, uint16_t len_without_crc) {
    uint8_t crc = 0;
    for (int i = 0; i < len_without_crc; i++) {
        crc += buf[i];
    }
    return (crc + 0xEC) & 0xFF;
}
```

## 3. 指令定义 (CMD)

| CMD | 十六进制 | 方向 | 说明 | Payload格式 |
| :--- | :--- | :--- | :--- | :--- |
| **WRITE** | 0x01 | 上位机→设备 | 写属性 | `[PID][Value] [PID][Value]...` |
| **READ** | 0x02 | 上位机→设备 | 读属性 | `[PID] [PID]...` |
| **NOTIFY** | 0x03 | 设备→上位机 | 属性通知/应答 | `[PID][Value] [PID][Value]...` |
| **ACK** | 0x04 | 设备→上位机 | 操作成功应答 | 无(或包含补充信息) |
| **ERROR** | 0x05 | 设备→上位机 | 错误应答 | `[Error String]` |
| **ACTION** | 0x06 | 上位机→设备 | 执行动作 | `[ActionID] [Params...]` |

## 4. 属性定义 (PID)

| PID名称 | 十六进制 | 数据类型 | 说明 |
| :--- | :--- | :--- | :--- |
| **SWITCH** | 0x01 | uint8 | 开关状态 (0:关, 1:开) |
| **MODE** | 0x02 | uint8 | 运行模式 (0:自动, 1:制冷, 2:除湿, 3:送风, 4:制热) |
| **TEMP_SET** | 0x03 | uint16 | 设定温度 (放大10倍传输, 如 26.5℃ 传 265) |
| **TEMP_ROOM** | 0x04 | int16 | 环境温度 (放大10倍传输) |
| **FAN_SPEED** | 0x05 | uint8 | 风速 (0:自动, 1:低, 2:中, 3:高) |
| **LOCK** | 0x06 | uint8 | 锁定状态 |
| **ERROR** | 0x07 | uint16 | 故障码 (按位定义) |
| **LORA_CFG** | 0x10 | Struct | Lora配置 |
| **IR_CFG** | 0x11 | Struct | 红外配置 |
| **DEV_INFO** | 0x12 | Struct | 设备信息 |
| **TIMESTAMP** | 0x13 | uint32 | 系统时间戳 (Unix时间戳,秒) |
| **SYS_PARAMS** | 0x14 | Struct | 系统运行参数查询 (16字节结构体) |
| **SYS_CTRL** | 0x15 | Struct | 系统参数控制 (6字节结构体) |
| **ALL_STATE** | 0xF0 | Struct | 全状态查询 (7字节结构体) |

## 5. 结构体详细定义

### 5.1 ALL_STATE 结构体 (7 Bytes)

用于读取和返回设备核心运行状态。

**偏移与数据:**

| 偏移 | 长度 | 字段 | 类型 | 说明 |
| :--- | :--- | :--- | :--- | :--- |
| 0 | 1 | switch | uint8 | 开关状态 (0:关, 1:开) |
| 1 | 1 | mode | uint8 | 运行模式 (0-4) |
| 2 | 2 | tempSet | uint16 | 设定温度 (×10) |
| 4 | 2 | tempRoom | uint16 | 环境温度 (×10) |
| 6 | 1 | fanSpeed | uint8 | 风速 (0-3) |
| 7 | 2 | errorCode | uint16 | 故障码 |

---

### 5.2 SYS_PARAMS 结构体 (16 Bytes)

用于读取系统运行参数。

**偏移与数据:**

| 偏移 | 长度 | 字段 | 类型 | 说明 |
| :--- | :--- | :--- | :--- | :--- |
| 0 | 2 | nodeId | uint16 | 节点ID |
| 2 | 1 | channel | uint8 | Lora通道 |
| 3 | 1 | loraStatus | uint8 | Lora状态 |
| 4 | 1 | scanCycle | uint8 | 扫描周期(秒) |
| 5 | 2 | irType | uint16 | 红外类型 |
| 7 | 1 | mode | uint8 | 工作模式 (0:本地, 1:远程) |
| 8 | 2 | errorCode | uint16 | 故障码 |
| 10 | 2 | tempRoom | uint16 | 环境温度 (×10) |
| 12 | 2 | runTime | uint16 | 运行时间(分钟) |
| 14 | 2 | loadPower | uint16 | 负载功率(W, ×10) |

---

### 5.3 SYS_CTRL 写入结构体 (6 Bytes)

用于写入系统参数控制。

**偏移与数据:**

| 偏移 | 长度 | 字段 | 类型 | 说明 |
| :--- | :--- | :--- | :--- | :--- |
| 0 | 2 | nodeId | uint16 | 节点ID |
| 2 | 1 | channel | uint8 | Lora通道 |
| 3 | 2 | irType | uint16 | 红外类型 |
| 5 | 1 | mode | uint8 | 工作模式 (0:本地, 1:远程) |

## 6. 上位机预期发送报文

### 6.1 设备调试页面 - 查询设备全部状态

**页面**: `pages/control/control.js`
**方法**: `queryDeviceState()`

**预期发送报文**:
```
04 02 F0 C8
```

**解析**:
- LEN: 0x04 (4字节)
- CMD: 0x02 (READ)
- Payload: 0xF0 (PID.ALL_STATE)
- CRC: 0xC8 = (0x04 + 0x02 + 0xF0) + 0xEC = 0x200 + 0xEC = 0x2C8 = 0xC8

**预期接收报文**:
```
0E 03 F0 [switch] [mode] [tempSet_L] [tempSet_H] [tempRoom_L] [tempRoom_H] [fanSpeed] [errorCode_L] [errorCode_H] [CRC]
```

示例(假设数据):
```
0E 03 F0 01 01 09 01 14 01 02 00 00 E9
```

---

### 6.2 设备调试页面 - 写入单个参数

**方法**: `updateParams(params)`

#### 6.2.1 切换开关(开启)

**输入**: `{ SWITCH: 1 }`
**预期发送报文**:
```
04 01 01 01 D7
```

**解析**:
- LEN: 0x04
- CMD: 0x01 (WRITE)
- Payload: 0x01 (PID.SWITCH) 0x01 (value=1)
- CRC: 0xD7 = (0x04 + 0x01 + 0x01 + 0x01) + 0xEC = 0x107 + 0xEC = 0x1F3 = 0xF3 (错误?)

**正确CRC计算**: (0x04 + 0x01 + 0x01 + 0x01) = 0x07, + 0xEC = 0xF3

#### 6.2.2 设置温度为 26.5℃

**输入**: `{ TEMP_SET: 26.5 }`
**预期发送报文**:
```
05 01 03 09 01 XX
```

**解析**:
- LEN: 0x05
- CMD: 0x01 (WRITE)
- Payload: 0x03 (PID.TEMP_SET) 0x09 0x01 (265 = 26.5×10, 小端)
- CRC: 0xXX

#### 6.2.3 批量写入(开关+温度)

**输入**: `{ SWITCH: 1, TEMP_SET: 26.5 }`
**预期发送报文**:
```
08 01 01 01 03 09 01 XX
```

**解析**:
- LEN: 0x08
- CMD: 0x01 (WRITE)
- Payload: 0x01 0x01 0x03 0x09 0x01
- CRC: 0xXX

---

### 6.3 系统参数页面 - 读取系统参数

**页面**: `pages/sysparam/sysparam.js`
**方法**: `readAllParams()`

**预期发送报文**:
```
04 02 14 XX
```

**解析**:
- LEN: 0x04
- CMD: 0x02 (READ)
- Payload: 0x14 (PID.SYS_PARAMS)
- CRC: 0xXX = (0x04 + 0x02 + 0x14) + 0xEC = 0x1A + 0xEC = 0x106 = 0x06

**预期接收报文**:
```
12 03 14 [nodeId_L] [nodeId_H] [channel] [loraStatus] [scanCycle] [irType_L] [irType_H] [mode] [errorCode_L] [errorCode_H] [tempRoom_L] [tempRoom_H] [runTime_L] [runTime_H] [loadPower_L] [loadPower_H] [CRC]
```

示例:
```
12 03 14 01 00 05 04 3C 00 01 00 00 10 00 2C 01 2C 01 XX
```

---

### 6.4 系统参数页面 - 写入系统控制参数

**页面**: `pages/sysparam/sysparam.js`
**方法**: `saveSysCtrl()`

**假设输入**: nodeId=1, channel=5, irType=1, mode=1

**预期发送报文**:
```
09 01 15 01 00 05 01 00 01 XX
```

**解析**:
- LEN: 0x09
- CMD: 0x01 (WRITE)
- Payload: 0x15 (PID.SYS_CTRL) 0x01 0x00 (nodeId=1) 0x05 (channel=5) 0x01 0x00 (irType=1) 0x01 (mode=1)
- CRC: 0xXX

---

### 6.5 系统参数页面 - 同步时间

**方法**: `syncTime()`

**假设时间戳**: 1700000000 (2023-11-14 22:13:20)

**预期发送报文**:
```
08 01 13 00 20 31 65 55 XX
```

**解析**:
- LEN: 0x08
- CMD: 0x01 (WRITE)
- Payload: 0x13 (PID.TIMESTAMP) 0x00 0x20 0x31 0x65 0x55 (1700000000, 小端)
- CRC: 0xXX

## 9. 上位机代码关键实现

### 9.1 帧构建逻辑

```javascript
// utils/protocol.js
const buildFrame = (cmd, payload = []) => {
  const payloadBytes = new Uint8Array(payload)
  const totalLen = 1 + 1 + payloadBytes.length + 1  // LEN + CMD + Payload + CRC
  const bytes = new Uint8Array(totalLen)

  bytes[0] = totalLen              // LEN
  bytes[1] = cmd                // CMD

  // 复制 Payload
  for (let i = 0; i < payloadBytes.length; i++) {
    bytes[2 + i] = payloadBytes[i]
  }

  // 计算并添加 CRC
  bytes[totalLen - 1] = calcCrc(bytes.slice(0, totalLen - 1))

  return bytes.buffer
}
```

### 9.2 CRC计算

```javascript
const calcCrc = (bytes) => {
  let crc = 0
  for (let i = 0; i < bytes.length; i++) {
    crc = (crc + bytes[i]) & 0xFF
  }
  return (crc + 0xEC) & 0xFF
}
```

### 9.3 数据发送

```javascript
// utils/bluetooth_helper.js
```

## 10. 调试检查清单

### 10.1 连接检查
- [ ] 蓝牙服务UUID是否匹配: `0000FFE0-0000-1000-8000-00805F9B34FB`
- [ ] 特征值UUID是否匹配: `0000FFE1-0000-1000-8000-00805F9B34FB`
- [ ] Notify是否已启用

### 10.2 报文检查
- [ ] 帧结构是否正确 (LEN + CMD + Payload + CRC)
- [ ] CRC计算是否正确 (累加 + 0xEC)
- [ ] PID值是否与下位机定义一致
- [ ] 数据大小端是否一致(小端模式)
- [ ] 温度值是否放大10倍

### 10.3 日志检查
在微信开发者工具控制台查看以下日志:
- `[sendCommand] 发送命令: ...` - 十六进制报文
- `[sendCommand] deviceId: ...` - 设备ID
- `[sendCommand] serviceId: ...` - 服务UUID
- `[sendCommand] charId: ...` - 特征值UUID
- `[sendCommand] 命令发送成功` 或失败信息
- `[sendCommand] 收到响应事件`
- `[sendCommand] 收到响应数据: ...` - 下位机返回数据

## 11. 常见问题排查

### 问题1: 下位机收不到报文
**可能原因**:
1. 特征值UUID不匹配
2. Notify未启用
3. 服务连接未建立
4. 报文格式错误

**排查方法**:
- 检查控制台输出的 serviceId 和 charId
- 使用串口助手查看下位机是否收到数据
- 检查帧格式和CRC是否正确

### 问题2: 收到响应但解析失败
**可能原因**:
1. CRC校验失败
2. 帧长度字段不匹配
3. PID不匹配预期

**排查方法**:
- 查看控制台日志中的原始十六进制数据
- 手动计算CRC校验
- 确认下位机返回的帧结构

### 问题3: 参数值错误
**可能原因**:
1. 大小端不一致
2. 温度未乘10
3. PID解析错误

**排查方法**:
- 确认下位机使用小端模式
- 检查温度值计算逻辑
- 对比协议文档和代码实现
