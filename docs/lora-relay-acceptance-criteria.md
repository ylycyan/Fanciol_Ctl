# LoRa 中继稳定性验收标准

> 目标: 中继链路必须支持稳定读取和稳定控制。未通过本文档验收前, 中继功能不得用于生产部署。

## 0. 容量策略

当前开发阶段采用两级容量:

| 阶段 | 每个中继允许子节点数 | 固件宏 |
|------|----------------------|--------|
| 试点阶段 | 4 | `RELAY_MAX_ACTIVE_CHILD_NODES = RELAY_TRIAL_MAX_CHILD_NODES` |
| 正式发布 | 8 | `RELAY_MAX_ACTIVE_CHILD_NODES = RELAY_RELEASE_MAX_CHILD_NODES` |

试点阶段必须先按 4 个/中继通过全部验收。正式发布前, 只允许在单中继满载和双中继压力测试均通过后把上限切到 8。

## 1. 验收拓扑

### 最小验收拓扑

```
网关
  |
中继 R1
  |-- 子节点 C1
  |-- 子节点 C2
  |-- 子节点 C3
  `-- 子节点 C4
```

### 压力验收拓扑

```
网关
  |-- 直连节点 D1..D8
  |-- 中继 R1 -> 子节点 C1..C8
  `-- 中继 R2 -> 子节点 C9..C16
```

除非特别说明, 所有验收必须在 `scanCycle=90s` 下执行。

## 2. 硬性通过标准

| 项目 | 通过标准 |
|------|----------|
| 子节点注册成功率 | 4 个子节点连续 20 次断电重启注册, 成功率 100% |
| 中继读取成功率 | 4 个子节点连续 24 小时轮询读取, 成功率 >= 99.9% |
| 中继控制成功率 | 每个子节点连续 100 次控制, 总成功率 >= 99.5%, 单节点不得低于 99% |
| 控制确认 | 每次控制必须收到 `cmd=0x0E` ACK 或明确失败码, 不允许静默成功 |
| 恢复能力 | 中继断电 5 分钟后恢复, 所有子节点在 2 个 scanCycle 内恢复在线 |
| 子节点离线识别 | 子节点断电后, 中继在 3 个 scanCycle 内将其标记离线 |
| 假在线 | 24 小时测试中 childBitmap 不允许出现持续超过 3 个 scanCycle 的假在线 |
| 主循环阻塞 | 任意 LoRa 转发流程不得阻塞 BLE/RTC/Flash/ADC/Rule 主循环超过 200ms |
| 看门狗 | 24 小时压力测试中不得触发 WDT 或异常复位 |
| 内存 | 压力测试后 RAM 使用不得增长, childTable 不得越界或重复插入同一 nodeId |

任一硬性标准失败即判定中继方案未通过。

## 3. 注册验收

### 3.1 中继节点注册

步骤:
1. 设置节点为 `LINK_RELAY`.
2. 重启节点 20 次.
3. 每次记录注册耗时和 LoRa 状态.

通过条件:
- 20 次全部进入 `Status_Connected`.
- 单次注册耗时 <= 60s.
- `PID_RELAY_CFG` 读取为 `linkRole=1`, `parentRelayId=0`.

### 3.2 子节点经中继注册

步骤:
1. 设置子节点为 `LINK_CHILD`, `parentRelayId=R1`.
2. 逐个重启 C1..C4, 每个节点 20 次.
3. 中继读取 `PID_RELAY_CFG`.

通过条件:
- 每个子节点 20 次全部注册成功.
- 子节点注册耗时 P95 <= 90s.
- 中继 `childCount` 与实际在线数量一致.
- `childBitmap` 对应位在 1 个 scanCycle 内更新.

## 4. 读取验收

### 4.1 24 小时读取稳定性

步骤:
1. 启动最小验收拓扑.
2. 网关按正常轮询周期读取 C1..C4.
3. 连续运行 24 小时.

必须记录:
- 总轮询次数.
- 每个子节点成功响应次数.
- 超时次数.
- CRC 失败次数.
- 中继重注册次数.
- 子节点重注册次数.

通过条件:
- 总读取成功率 >= 99.9%.
- 单个子节点读取成功率 >= 99.5%.
- 不允许连续 3 次读取失败.
- 不允许中继状态机卡在非 `Status_Connected` 超过 2 个 scanCycle.

## 5. 控制验收

### 5.1 单节点控制

步骤:
1. 对 C1 连续发送 100 次控制命令.
2. 命令类型至少覆盖开机、关机、模式、温度、风速.
3. 每次必须等待 ACK 或失败码.

通过条件:
- 成功 ACK >= 99 次.
- 不允许命令顺序错乱.
- 不允许重复执行同一 token.
- 控制 ACK P95 延迟 <= 2s.
- 控制 ACK 最大延迟 <= 5s.

### 5.2 多子节点交替控制

步骤:
1. 按 C1 -> C2 -> C3 -> C4 循环发送控制.
2. 每个子节点 100 次, 总计 400 次.

通过条件:
- 总成功率 >= 99.5%.
- 任一子节点成功率 >= 99%.
- 不允许 ACK 被归属到错误 nodeId.
- 不允许中继在等待一个子节点 ACK 时吞掉其他网关轮询包并长期不恢复.

## 6. 故障恢复验收

### 6.1 中继断电恢复

步骤:
1. 所有子节点在线.
2. 中继断电 5 分钟.
3. 恢复中继供电.

通过条件:
- 子节点不降级直连.
- 中继恢复后, 子节点在 2 个 scanCycle 内恢复读取.
- 恢复后控制成功率仍满足第 5 节.

### 6.2 子节点断电恢复

步骤:
1. C1 断电 5 分钟.
2. 保持 C2..C4 在线.
3. 恢复 C1 供电.

通过条件:
- C1 在 3 个 scanCycle 内从 childBitmap 离线.
- C2..C4 不受 C1 断电影响.
- C1 恢复后在 2 个 scanCycle 内重新在线.

## 7. 容量验收

### 7.1 单中继满载

拓扑:
- R1 下挂 C1..C8.

通过条件:
- 8 个子节点读取成功率 >= 99%.
- 8 个子节点交替控制成功率 >= 99%.
- 24 小时内不允许出现中继状态机死锁.

### 7.2 双中继压力

拓扑:
- R1 下挂 C1..C8.
- R2 下挂 C9..C16.
- 直连 D1..D8.

通过条件:
- 全网读取成功率 >= 99%.
- 中继子节点控制成功率 >= 99%.
- 直连节点不因中继节点存在而明显劣化, 成功率下降不得超过 0.5%.

## 8. 必须输出的测试证据

每轮验收必须保存以下证据:

1. 固件 git commit hash.
2. 上位机 git commit hash.
3. 网关固件版本.
4. 节点角色配置表: nodeId, linkRole, parentRelayId, channel.
5. 原始串口日志.
6. 网关轮询统计.
7. 控制命令统计: token, targetNodeId, sendTime, ackTime, result.
8. `PID_RELAY_CFG` 周期读取快照.
9. 异常列表和复测结果.

## 9. 发布门禁

只有同时满足以下条件, 才允许发布中继固件:

- 最小验收拓扑全通过.
- 单中继满载全通过.
- 控制 ACK 已实现并通过.
- 中继断电恢复和子节点断电恢复全通过.
- 24 小时稳定性测试无死锁、无 WDT、无异常复位.
- 所有 P0 缺陷关闭并复测通过.

压力验收拓扑未通过时, 允许小规模试点, 但必须限制为:
- 每个中继最多 4 个子节点.
- 全网总节点数不超过 20.
- 必须开启服务器侧离线告警和控制失败重试。
